## seed没有覆盖实际使用的随机性

冻结路径相对于44的
`/root/new-scii-empty-bo-frame-20260907/code-ca7885d/agent_system/environments/env_package/sc2_online_restored/`：

| 代码 | 实际行为 |
| --- | --- |
| `envSC2.py:376,536–546,164–171` | seed传给子进程和`run_game(random_seed=seed)`，但子进程未调用`random.seed(seed)` |
| `envSC2.py:675–677` | 另一层设置NumPy随机流，不控制Python random |
| `SC2ArenaDyStrategy/players/script_player.py:2890` | `scv_pool.random`选择侦察工人 |
| 实装burnysc2 7.1.3的`sc2/units.py:139–141` | 上一项实际是`random.choice(self)` |
| `SC2ArenaDyStrategy/players/base_player.py:701–706,635–637` | 建筑显式启用`random_alternative=True`，从可行位置`random.choice(possible)` |
| 同文件719–737行 | 用重新计算的`target`发命令，但记录的`action`未回填真实落点 |

因此日志的`[1,1]`是占位值，**不是把建筑造在地图角落**。两条打印命令相同，也
可能执行到不同的位置。随机选址本身并非错误；缺口是配对seed没有绑定这条随机流。

现场Python为3.12.3，`random.py:992`注册fork后重新seed；新解释器的默认
multiprocessing方式是fork。历史worker实际start method未记录，不冒充已核验
其当时值。无论如何，父进程NumPy/训练seed不能证明游戏子进程Python随机流配对。

这是具体的可复现性缺口和早期分岔候选来源，不是已经证明的整局失败根因。
00:23前未消费Planner回答，执行器走冻结的本地规则；没有证据将其归因于Qwen、
PPO或模型精度。

## 不能把早期延迟直接当成最终败因

BO#12在01:40就再次对齐，BO#92–179共88项的**开始时间**也完全一致。两个长等待
两边都有，不能当成step8新增故障：

| BO | 两局共同开始→结束 | 原因 |
| --- | --- | --- |
| #110 reactor barracks | 06:17→06:56 | `Ability 'BUILD_REACTOR_BARRACKS' not currently available.` |
| #114 reactor barracks | 06:57→07:36 | 同上；均11次尝试后跳过 |

08:37累计采矿为12540对12575，step8还略高；军队人口却为29对20、建筑数44对42。
step8工人随后在09:13/09:31/09:49/10:25降为44/36/29/2，早于10:39首次Planner。
所以不能说“少采几矿造成四秒延迟，之后一路积累到崩盘”。

自动首攻也不同：iteration1901对2005（约05:39对05:58），集结点`(29,87)`对
`(29,84)`，首次Planner前自动出兵共8对3次。这证明固定队列相同不等于实际
生产、行军和交战相同，但没有证明哪个波次是败局唯一原因。

## 旧日志还缺什么

初评`trace.json`与目标worker的208条打印命令全部一致，终局1343秒也一致。
据135帧观测，首座供给站在`(29,27)`；515帧记录155矿，支持上述资源门槛解释。

**step8的trace已不是目标局**：与目标worker仅48条命令一致，119条缺失、38条
冲突；终局1058秒，而目标局765秒。八局共用秒级目录，文件被覆盖。独立观测
文本也串局：初评112帧文件写基地`(127,22)`，已核对的trace却是`(24,22)`；
step8的135帧文件又是基地`(24,125)`的另一局。不能拿这些文件补目标局证据。

仍缺step8目标局首座建筑真实落点、逐工人位置/订单、随机选择和RNG状态。
`[1,1]`不能恢复这些值，也不能据别局观测宣称两次落点一定不同。历史文件未修改。

## 唯一下一项建议

只读分析已解释第一处BO延迟，并确认随机性控制和逐局证据的缺口；**没有完成
“哪次随机选择造成最终崩盘”的因果定位**。不因此改PPO或直接续长训。

若继续，建议另行批准最小验证：独立候选只在SC2子进程按已有episode seed固定
Python RNG，两次同seed的固定BO短局各到2分钟，不调用模型、不占GPU。每局用
独立输出目录，核对资源、建造落点、BO帧号是否复现。唯一行为变量是RNG绑定，
不改选址算法、战术、Planner接管时机或训练；本轮未实施、未启动。
